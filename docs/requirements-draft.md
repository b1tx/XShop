# 系统需求文档初稿

## 1. 项目可行性分析

### 1.1 领域边界

本系统属于 B2C 在线零售领域，覆盖消费者从商品浏览到下单支付的购物流程，以及运营人员对商品、订单、促销、库存和销售数据的管理流程。

系统不覆盖真实物流、真实第三方支付、供应链采购、财务结算和多商户分账。

### 1.2 目标用户

- 普通用户：浏览商品、搜索商品、加入购物车、下单、支付、查看订单、使用 AI 导购。
- 运营管理员：维护商品、分类、库存、促销活动，处理订单，查看销售数据，使用 AI 运营助手。
- 系统管理员：管理用户、角色、权限和系统日志。

### 1.3 用户需求

- 普通用户需要快速找到适合自己的商品，并完成稳定的购物流程。
- 运营管理员需要高效维护商品和订单，并通过数据了解销售情况。
- 系统管理员需要控制后台权限，保证重要操作可追踪。
- 所有用户都可以通过 AI 功能降低信息筛选和运营分析成本。

### 1.4 竞品分析

对比京东、淘宝、拼多多等成熟电商平台，本系统规模更小，不追求完整商业闭环，而聚焦课程项目可实现的核心能力：

- 优势：功能边界清晰，前后端分离，AI 导购和运营辅助集成度高，适合本地演示。
- 劣势：不包含真实支付、真实物流、多商户结算和大规模推荐算法。

## 3. 客户端与服务端职责

客户端：

- 展示商品、购物车、订单、后台表格和图表。
- 处理路由跳转、表单校验、登录态保存和交互反馈。
- 通过 Axios 调用后端 API。

服务端：

- 提供认证、商品、订单、库存、促销、AI 和看板接口。
- 负责权限校验、业务规则、事务一致性和数据持久化。
- 调用 OpenAI 兼容 API 并保存 AI 交互记录。

## 4. 权限方案

- 普通用户：访问商城前台、购物车、订单、AI 导购。
- 运营管理员：访问后台商品、订单、库存、促销、看板、AI 运营助手。
- 系统管理员：拥有全部后台权限，并可管理用户角色。

## 5. 主要用例

- 用户注册登录。
- 用户搜索商品。
- 用户加入购物车。
- 用户提交订单并模拟支付。
- 用户取消订单。
- 运营管理员新增商品。
- 运营管理员配置限时抢购。
- 运营管理员处理订单发货。
- 系统管理员管理用户角色。
- 用户使用 AI 导购获取购买建议。
- 运营管理员使用 AI 生成商品文案和销售分析。

## 6. 原型说明

首版原型以可运行页面为主：

- 商城首页：分类导航、商品列表、搜索框、AI 导购入口。
- 商品详情：商品图片、价格、库存、详情、加入购物车按钮。
- 购物车：商品行、数量修改、合计金额、结算按钮。
- 订单页：订单状态、商品明细、支付/取消/确认收货按钮。
- 后台商品管理：筛选区、商品表格、新增/编辑弹窗、上下架按钮。
- 后台看板：核心指标、趋势图、热销榜、库存预警。
